# Сравнение RAG Tender с Codant — протокол к показу 16 октября

**Цель:** не сравнение дизайна сайта, а доля технически допустимых товаров LD на одинаковой входной выборке.

## Зафиксировать входы (до просмотра результатов)

1. Исторические 20 строк настоящих тендеров (`data/tender_queries_v1_harness_cases.json`, branch prod/rag-tender-exp4): 11 CORE и 9 EXTENDED; human positive IDs неисчерпывающие.
2. Frozen-100 seed 53: использовать исходную версию и provenance из проекта, а не 100 новых подобранных вручную удобных случаев.
3. Дополнительно 10–20 новых, не использовавшихся при улучшении запросов, чтобы исключить переобучение. Список запечатать **до** сравнения.

## Одна строка — один запрос — два независимых результата

Текст строки передать конкуренту и своему API **дословно одинаковый**. Записывать timestamp, исходный запрос, выбранный артикул, 2–3 лучших альтернативы, время, статус ошибки, категорию найденного товара.

### Ручной экспертный verdict для каждой системы

- **PASS** — артикул существует в LD и совпадает со всеми обязательными техническими условиями (включая неподдерживаемые автоматически требования).
- **PARTIAL** — нет данных по одному или нескольким критичным полям, требуется паспорт/инженер.
- **FAIL** — имеется доказанное противоречие требованиям.
- **NOT_FOUND** — система не подтвердила подходящего товара.
- **ERROR** — инфраструктура/модель не дала результата.

При наличии разных, но обоих PASS артикулов обе системы получают PASS. Точный GOLD ID дополнительно учитывается, но не подменяет техническую корректность.

## Отчёт

Для каждой системы вывести:

- strict PASS@1 (главный показатель) и PASS@3 (любая из первых трёх LD альтернатив полностью совместима);
- ошибочные MATCHED (false match), ошибочные NOT_FOUND (если известно, что пригодный LD существует);
- coverage с явным отделением PARTIAL;
- latency p50/p95 и долю API ошибок;
- 5 конкретных успешных примеров и 5 ошибок с указанием противоречащего поля.

Слепая экспертная проверка предпочтительнее: эксперт не должен видеть названия систем в протоколе до выставления verdict.

**Сейчас нет верифицированных результатов Codant.** Сайт https://ld-proto.codant.ru/#/spec недоступен инструментам удалённого просмотра. Не публиковать утверждения, что мы лучше, пока обе системы не проверены на одной выборке.

## Приоритетный риск нашего решения

Frozen-100 E08: 93% acceptable ID в широком пуле, 84% дошли до reranker, 34% точное top-1 попадание. Главный наблюдаемый резерв — ошибки финального выбора, а не красивый интерфейс. Не пытаться лечить это только добавлением альтернатив: альтернативы должны пройти строгую проверку перед тем, как быть названы технически подходящими.

Для улучшения отдельно экспериментировать с deterministic first-pass проверки по всем явным техническим условиям, затем selective reranking, но **не менять live champion без повторного frozen-20/frozen-100 eval и проверки регрессий**.
