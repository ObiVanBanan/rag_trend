# RAG Tender observability

This branch keeps the validated matching behavior and adds instrumentation only.

## What is emitted

- `GET /metrics` in Prometheus text format.
- `X-Request-ID` is accepted from callers or generated by the API.
- The same request ID is returned in the response header/JSON and stored in PostgreSQL.
- Structured `match_trace` JSON logs expose stage timing without putting product text into Prometheus labels.

Main stages:

```text
request
  -> item
    -> interpreter
    -> embedding
    -> qdrant
    -> rerank
  -> persist
  -> response
```

Metrics use the `rag_tender_` prefix and cover HTTP, item outcomes, batch size,
query interpretation, embeddings, Qdrant, reranking, and PostgreSQL history writes.

## Shared monitoring network

The production compose expects one external Docker network:

```bash
docker network inspect rag-observability-net >/dev/null 2>&1 || docker network create rag-observability-net
```

The API uses a private `backend` network for application traffic and joins
`rag-observability-net` only so the shared monitoring stack can reach it.

Qdrant and PostgreSQL are no longer published on host ports in this branch.
They remain reachable from the application private network and the shared
observability network.

## Smoke test

```bash
curl http://127.0.0.1:8000/metrics | grep rag_tender_
curl -i -X POST http://127.0.0.1:8000/v1/match \
  -H 'Content-Type: application/json' \
  -H 'X-Request-ID: tender-smoke-001' \
  -d '{"products":["Кран шаровой стальной фланцевый Ду50 Ру16 полнопроходной"]}'
```

Then search Loki/Grafana for `request_id=tender-smoke-001`.
